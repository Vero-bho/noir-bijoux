# SQL-скрипты для PostgreSQL (Supabase) — основной вариант базы

База проекта — **PostgreSQL в облаке Supabase** (так указано в методических
указаниях: практические занятия №7 и №8). Отдельный сервер устанавливать не
нужно: база живёт на сайте `supabase.com`, все скрипты выполняются в браузере
в разделе **SQL Editor**.

## Порядок выполнения

| № | Файл | Что делает | Повторный запуск |
|---|---|---|---|
| 00 | `00_create_all_simple.sql` | **всё в одном**: таблицы + индексы + данные + проверка | ошибка «already exists», если таблицы уже есть |
| 01 | `01_schema.sql` | 12 таблиц, 12 связей, уникальные ограничения, индексы из схемы | ошибка «уже существует» — это нормально |
| 02 | `02_indexes.sql` | 7 индексов по внешним ключам и статусам заказов | безопасен (`IF NOT EXISTS`) |
| 03 | `03_seed.sql` | данные магазина: 8 изделий, 40 компонентов, пользователи, сборки, заказы | безопасен (сначала очищает таблицы) |
| 04 | `04_verify.sql` | 11 запросов проверки — для отчёта и скриншотов | в любой момент |
| 05 | `05_drop.sql` | удаляет все таблицы (начать с нуля) | безопасен |

Для Supabase достаточно **одного файла `00_create_all_simple.sql`**.
Остальные — тот же результат по шагам (удобно для отчёта: видно каждый этап).

## Как выполнить в Supabase

1. Войти на <https://supabase.com> → выбрать проект → **SQL Editor**.
2. **New query** → вставить файл → **Run**.
3. Проверить результат в **Table Editor** (таблицы и данные) и в
   **Database → Indexes** (индексы).

## Как выполнить из командной строки (psql)

```bash
psql "postgresql://postgres.<ref>:<пароль>@aws-0-<регион>.pooler.supabase.com:5432/postgres" -f 00_create_all_simple.sql
```

## Через Prisma (альтернатива)

```bash
cd backend
npx prisma migrate deploy     # применяет 01_schema.sql (миграция в src/prisma/migrations)
npm run seed                  # заливает данные магазина из src/prisma/seed.ts
npm run db:check              # проверка подключения и данных
```

## Как создаются файлы 01 и 03

Вручную их не пишут — они генерируются из схемы и данных проекта:

```bash
python3 _tools/generate_sql_postgres.py   # 01_schema.sql, 02_indexes.sql, 03_seed.sql, 04_verify.sql, 05_drop.sql, 00, README
python3 _tools/generate_sql.py            # только схема и миграция (тот же результат, что 01)
```

`01_schema.sql` — это ровно тот SQL, который Prisma применяет командой
`npx prisma migrate deploy` (файл `src/prisma/migrations/20261007120000_init/migration.sql`).

## Проверка без интернета

Структуру и данные скриптов можно проверить, не подключаясь к Supabase:

```bash
cd backend
npm run test:sql:pg     # 40+ проверок: таблицы, связи, типы, данные, индексы
```

## Вариант для MS SQL Server

Прежние скрипты для Microsoft SQL Server остались в папке `backend/sql/`
(они пригодятся, если в отчёте нужно сравнить две СУБД). Текущий бэкенд
настроен на PostgreSQL — строка подключения описана в `backend/.env.example`.
